# 0002 · PR 合并策略选 Squash

**日期**：（今天）
**状态**：生效中

## 背景
（提 PR 时分支上可能有好几次提交——写错改一次、格式调一次。
main 的历史要不要保留这些中间过程？）

## 选项
1. Merge commit —— 保留分支上每一条提交，加一条合并提交
2. Squash merge —— 把分支上所有提交压成一条，再合并
3. Rebase —— 把分支上的提交逐条"移植"到 main 上，不额外加合并提交

## 决定
（选了哪个）2

## 理由
（为什么。提示：一个 PR 对应几条 main 历史记录，对"半年后想知道
这个功能是哪个 PR 加的"这件事，哪种更方便？）

## 代价
（提示：分支上的中间提交——包括你改错又改回来的过程——被丢弃了，
这算不算损失？）
